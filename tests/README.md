# 配置生命周期回归验证

## 自动化检查

```sh
pnpm test
cargo test --manifest-path src-tauri/Cargo.toml config_watch::tests
```

前端测试覆盖重复初始化、配置暂时缺失后重新加载、事件订阅失败和启动降级。Rust 测试覆盖通知过滤，以及 Windows 文件锁允许读写、拒绝删除/改名、释放后允许改名。

Rust 测试需要项目原有的 Windows 构建环境。当前 vendor 的 GNU CRT shim 在 MSVC 下有重复符号问题，最新 Rust 调试构建中的 single-instance 插件也有既存启动问题；本次完整程序回归在隔离测试副本中绕过了这两项，未将这些无关改动纳入修复。

## 完整程序检查

1. 打开设置，关闭后确认窗口隐藏；重新打开应恢复同一窗口及页面状态。检查自定义关闭按钮、Esc 和系统关闭事件。
2. 重复开关设置 30 次并空闲观察，主进程的线程和句柄不应按开关次数线性增长。
3. 程序运行期间，尝试对隔离配置的 `config.json` 删除、改名或移动，Windows 应拒绝操作；原地读写仍可进行。
4. 原地修改有效 JSON，确认后台配置自动重载。写入无效 JSON 时应保留缓存并记录错误，恢复有效 JSON 后应继续重载。
5. 退出程序后，应能正常改名或移动配置文件。
6. 在文件保护不可用的隔离测试中，使配置文件缺失后首次打开设置，界面应仍能显示；恢复配置文件后应自动重载。

配置文件监听和窗口尺寸防抖各由一个应用级工作线程处理。设置窗口通过保存状态并隐藏来复用 WebView，不再为每次打开分配一个新窗口。Windows 文件保护持有只读句柄，允许共享读写但不共享删除；外部编辑器若通过“临时文件替换原文件”保存，也会受到改名限制，需要使用原地写入。
