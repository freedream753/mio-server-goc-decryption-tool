## 与主线版本的区别

主线（`main` 分支）通过截屏 + 系统内置 OCR 自动识别游戏画面给出答案；本支线基于同一套核心算法，**完整移除了截图、裁切、OCR 与屏幕识别能力**，改为手动输入 / 手绘交互，适合不需要自动识别、或希望工具完全不接触屏幕内容的场景：

| 能力 | 主线 v1.1.0 | 本支线 v1.2.0-noocr |
|---|---|---|
| 第一关 校准 | 自动识别波形面板 | 空白画布手绘目标曲线 → 自动拟合出四滑块 |
| 第二关 西蒙 | 全自动录制序列 | 已移除 |
| 第三关 解密 | 自动识别符盘 + minimax 推荐 | 手动录入猜测与反馈色 + 同款 minimax 推荐 |
| 截图 / OCR / 裁切模式 | 有 | 全部移除，程序不读取屏幕 |

## 功能特性

1. **两关解题助手：** 结果窗口内置校准 / 解密两个页签，默认快捷键 `Alt + X`（校准）、`Alt + V`（解密），均为「呼出结果窗口并切换到对应页签」，可自行修改。

2. **校准（第一关 · 画线拟合）：** 在结果窗口的空白网格画布上按住鼠标，对照游戏内目标曲线画出一条线，松开即自动拟合双正弦（基波 + 二次谐波）参数，给出振幅 / 频率 / 相位 / 偏移四个滑块答案，并绘制拟合曲线供比对；支持清空重画与重新拟合。

3. **解密（第三关 · 四位符文）：** 手动选择四个符文、按游戏反馈标注红 / 黄 / 绿颜色，采用「候选优先、搏直接命中」的 minimax 策略（首猜固定「空火水风」）在 4 次提交内破解；支持推荐、撤回、历史记录与新一局。

4. **零屏幕读取：** 程序不含任何截图、OCR、裁切或屏幕识别代码路径，不读取屏幕任何像素，仅做纯数学计算——体积也更小（x64 约 30MB，主线约 39MB）。

5. **不抢焦点结果窗口：** 结果窗口始终置顶且不夺取游戏焦点（WS_EX_NOACTIVATE）；支持鼠标点击答案行直接复制。

6. **界面多语言：** 内置简体中文与 English 两套界面（含托盘菜单与符文名），可在设置页切换。

7. **单文件离线：** 无外部 DLL 依赖、零网络请求（本地 HTTP 接口仅供外部脚本呼出窗口用）。

## 工作流程

```
热键（Alt+X / Alt+V）或托盘菜单呼出结果窗口并切到对应页签
    ↓
校准页：在空白网格画布上按住鼠标画出游戏内目标曲线，松开
    ↓
后端等距重采样 → 双正弦网格搜索 + 线性最小二乘拟合（R²≥0.5 校验）
    ↓
输出振幅 / 频率 / 相位 / 偏移四个滑块答案 + 拟合曲线预览，点击复制

解密页：手动录入猜测与反馈色 → Web Worker 本地跑 minimax → 展示推荐提交
```

## 使用方法

1. 运行 exe，程序驻留系统托盘；托盘菜单「打开解题助手」呼出结果窗口，「偏好设置」修改热键 / 语言 / 开机自启
2. 校准（第一关）：按 `Alt + X` 呼出校准页 → 在网格画布上按住鼠标，对照游戏内波形从左到右画一条线 → 松开自动求解，照抄四个滑块即可；画得不像会提示重画（R² 校验）
3. 解密（第三关）：按 `Alt + V` 呼出解密页 → 手动点选四个符文并按游戏内反馈标注颜色 → 点击推荐提交，根据反馈更新颜色，直至破解或 4 次用尽开新一局
4. 关闭结果窗口（`Esc` 或右上角 ×）程序继续驻留托盘

> 系统要求：Windows 10 及以上；不依赖任何 OCR 语言包。

## 技术实现

- **波形拟合内核**（`src-tauri/src/wave.rs`）：算法移植自 11.9 版验证过的 `fit_two`——双正弦（基波 + 二次谐波）网格搜索频率粗搜 + 线性最小二乘 + 坐标下降联合微调；手绘点在后端先按 x 升序去重、线性插值等距重采样 400 点，避免密集段带偏频率粗搜；R²≥0.5 质量校验；`to_sliders` 逆映射为 0~100 滑块
- **手绘画布**（`src/window/Result/pages.jsx`）：SVG viewBox 0~100 + `preserveAspectRatio="none"`，指针事件采集归一化点集（x∈[0,1]、y∈[-1,1] 向上为正），画布同时叠画手绘线与拟合曲线
- **推荐引擎**（`src/utils/runes.js` + Web Worker）：1296 候选的候选优先 minimax，本地离线计算下一步提交，与主线同款
- **多语言**（`src/i18n/`）：i18next 实现，zh_CN / en_US 两套语言包
- **三架构构建**：x64（x86_64-pc-windows-gnu）、x86 / ARM64（llvm-mingw gnullvm），产物均通过 PE 头与文件版本校验；WebView2Loader 已静态嵌入，均为真正的单文件

## 从源码构建

```bash
pnpm install
pnpm tauri build
```

> **注意路径**：源码与 `CARGO_TARGET_DIR` 所在路径必须为纯 ASCII 字符。路径含中文时（如本机 E 盘目录），cargo 会将路径规范化回真实中文路径，导致链接器 ld.exe 找不到 rlib 而构建失败——建议把仓库放在纯 ASCII 路径，或通过 `CARGO_TARGET_DIR` 把构建产物指到 ASCII 路径。

## 常见问题

<details>
<summary><b>按快捷键没有反应？</b></summary>

确认程序在托盘运行中。支线版本的热键只负责「呼出结果窗口并切页签」，不再触发任何识别；窗口可能在呼出时所在屏幕，注意检查多显示器场景。
</details>

<details>
<summary><b>校准页提示「画线点太少 / 拟合质量不足」？</b></summary>

请沿画布从最左画到最右、尽量贴合游戏内目标曲线（拟合需要 R²≥0.5）。画完后画布会同时显示手绘线（蓝）与拟合线（橙），可目检对比后点「重新拟合」。
</details>

<details>
<summary><b>窗口拖到另一个屏幕不见了？</b></summary>

窗口拖动不允许跨屏幕，仅允许在呼出时所在的屏幕内移动；如需在另一屏幕使用，请关闭窗口后在该屏幕重新按快捷键呼出。
</details>

## 更新日志

### v1.2.0-noocr · 不使用 OCR 支线

基于主线 v1.1.0 派生的精简支线（`noocr` 分支）：

1. **全面移除 OCR 与屏幕识别：** 截图管线、全局裁切模式、裁切指示窗、框选窗、WinOCR 封装、识别热键路径全部删除，删除 `solver.rs` / `runes.rs` / `simon.rs` / `screenshot.rs` 四个模块，程序不再读取屏幕任何内容
2. **移除第二关西蒙：** 页签、录制管线、`Alt + C` 热键全部退役
3. **第一关改为画布手绘：** 空白网格画布 + 指针采集 + 后端 `fit_points` 拟合（重采样 + `fit_two` 双正弦拟合 + R² 校验），输出与主线一致的 payload（四滑块 + 曲线参数）
4. **第三关保留核心算法：** 前端 minimax 推荐引擎原样保留，仅移除 `rune_recognize` 自动识别入口，全流程手动录入
5. **入口调整：** `Alt + X` / `Alt + V` 改为呼出结果窗口并切页签；托盘菜单改「打开解题助手」；本地 HTTP 仅剩 `/`（呼出窗口）与 `/config`
6. **体积瘦身：** 移除截图 / OCR 相关依赖，x64 产物从 39MB 降至 30MB
